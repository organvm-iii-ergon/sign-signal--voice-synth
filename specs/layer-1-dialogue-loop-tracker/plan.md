# Implementation Plan: Dialogue Looping Tracker Sequence (Layer 1)

**Branch**: `layer-1-dialogue-loop-tracker` | **Date**: 2026-03-30 | **Spec**: `spec.md`

## Summary

Build a dialogue looping tracker sequence as Layer 1 of the Speech Score Engine. Users paste dialogue text, which is parsed into phrase-events with speaker detection. Each phrase can be configured with loop patterns (repeat count, stagger timing, duration mode) and played back with real-time visual tracking. Supports multiple TTS providers (Coqui, VALL-E, ElevenLabs) with voice cloning capability and versioning system.

## Technical Context

**Language/Version**: TypeScript (Next.js 14), Python 3.11 (FastAPI)  
**Primary Dependencies**: Next.js 14 (App Router), FastAPI, Prisma, Redis, Tailwind CSS  
**Storage**: PostgreSQL (Prisma ORM), Redis (caching + playback state)  
**Testing**: Vitest (frontend), pytest (backend)  
**Target Platform**: Web application (browser-based playback)  
**Project Type**: Full-stack web application  
**Performance Goals**: Playback seeking <200ms, scene with 100 phrases loads without degradation  
**Scale/Scope**: Single user per session, scenes up to 500 phrases

## Implementation Phases

### Phase 0: Infrastructure (Week 1)

- Set up Next.js 14 project with TypeScript + Tailwind
- Set up FastAPI backend with Prisma
- Configure PostgreSQL + Redis via Docker Compose
- Implement speaker parsing algorithm from raw text

### Phase 1: Core CRUD (Week 2)

- Scene creation and management
- Speaker CRUD with voice profile assignment
- PhraseEvent CRUD with all loop/sequence config fields
- Real-time phrase reordering via drag-drop

### Phase 2: TTS Integration (Week 3)

- Implement TTS provider abstraction (interface pattern)
- Integrate ElevenLabs API (fastest path to working TTS)
- Add Coqui TTS as open-source alternative
- Audio caching strategy with Redis

### Phase 3: Playback Engine (Week 4)

- Generate full sequence audio on backend
- WebSocket for real-time playback progress
- Play/pause/stop/seek controls
- Visual playback tracker (current phrase highlight)

### Phase 4: Versioning (Week 5)

- Version save/restore functionality
- Version comparison (text diff + duration delta)
- Scene snapshot serialization

### Phase 5: Polish (Week 6)

- Voice cloning integration
- Per-speaker speech rate/pitch controls
- Performance optimization for 100+ phrase scenes
- Error handling and edge cases

## Key Technical Decisions

### TTS Provider Abstraction

```python
class TTSProvider(ABC):
    @abstractmethod
    async def generate(self, text: str, voice: VoiceProfile) -> bytes: ...
    @abstractmethod
    async def preview(self, voice: VoiceProfile) -> bytes: ...
    @abstractmethod
    async def clone_voice(self, sample_url: str) -> VoiceProfile: ...

class ElevenLabsProvider(TTSProvider):
    ...

class CoquiProvider(TTSProvider):
    ...
```

### Playback Architecture

- Backend generates WAV for full sequence
- Frontend uses Web Audio API for playback
- WebSocket broadcasts: phrase_start, phrase_end, playback_complete
- Seek via Audio.currentTime calculation

### Audio Caching

- Redis key: `audio:{scene_id}:{phrase_hash}:{voice_id}`
- TTL: 24 hours (configurable)
- Invalidation: on phrase text change or voice config change
